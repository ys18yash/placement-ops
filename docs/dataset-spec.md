# PlacementOps Dataset Specification

## Dataset Size

- 35 companies
- 800 students
- 20 rooms
- 4 placement days
- Variable number of panels
- Shortlists generated from eligibility, company popularity, and company capacity
- One interview per valid student-company shortlist

## Companies

Each company must have:

- ID
- Name
- Industry
- Priority tier
- CGPA cutoff
- Interview duration
- Panel count
- Placement-day availability
- Time-window availability
- Popularity score

Priority tiers:

- P1
- P2
- P3
- P4

Companies must have different popularity and candidate volumes.

Day-1 companies should include higher-volume recruiters.

## Students

Each student must have:

- ID
- Name
- Branch
- CGPA
- Status
- Availability

Statuses:

- ACTIVE
- WITHDRAWN

CGPA should follow a realistic distribution rather than a uniform
random distribution.

Higher-CGPA students should generally qualify for more companies.

## Rooms

Generate exactly 20 rooms.

Each room must have:

- ID
- Name
- Building
- Floor
- Capacity
- Availability
- Status

Status:

- AVAILABLE
- UNAVAILABLE

## Panels

Each panel belongs to exactly one company.

Each panel must have:

- ID
- Company ID
- Name
- Availability
- Status

Status:

- AVAILABLE
- DROPPED

## Availability

Availability must be represented using:

- Day
- Start time
- End time

Placement week contains:

- DAY_1
- DAY_2
- DAY_3
- DAY_4

Use a consistent operating window, while allowing deterministic
variation in start and end times across companies, rooms, panels,
and students.

## Shortlists

Shortlists must not be generated completely randomly.

Shortlist generation should consider:

- Student CGPA
- Company CGPA cutoff
- Company popularity
- Company panel capacity
- Company availability
- Student/company selection probability
- Existing shortlist counts so the distribution is realistic rather
  than cliff-shaped

High-CGPA students should generally receive more shortlists.

Popular companies should shortlist more students on average.

This should naturally create overlapping shortlists and scheduling pressure
without making the full dataset globally impossible before scheduling.

## Interviews

Create one interview for every valid student-company shortlist.

Each interview must contain:

- ID
- Student ID
- Company ID
- Duration
- Status

Initial status:

UNSCHEDULED

Scheduling information must NOT be generated by the dataset generator.

Scheduling will be handled by a separate scheduling engine.

## Random Seed

The generator must accept a configurable random seed.

The same seed must produce the same dataset.

Default seed:

20260829

## Validation Rules

Validate:

- Exactly 35 companies
- Exactly 800 students
- Exactly 20 rooms
- Valid company references
- Valid student references
- Valid panel references
- Valid shortlist references
- Valid interview references
- No duplicate shortlists
- No duplicate interviews
- CGPA range validity
- Valid availability windows
- Every panel belongs to an existing company
- Every interview corresponds to a valid shortlist
- Capacity sanity thresholds
- Reasonable active zero-shortlist percentage
- Positive CGPA-to-shortlist relationship
- Positive popularity-to-shortlist relationship

## Dataset Statistics

The generator must output:

- Company count
- Student count
- Active student count
- Withdrawn student count
- Room count
- Panel count
- Shortlist count
- Interview count
- Average shortlists per student
- Average shortlists per active student
- Shortlist distribution including 0, 1-3, 4-7, 8-15, and 16+
- Shortlists per company
- CGPA statistics
- CGPA band statistics
- Company popularity statistics
- Total interview duration
- Total room capacity
- Total panel capacity
- Demand/capacity ratios
- Per-day estimated demand based on company-day capacity

## Disruption Scenarios

Create data structures that can later support:

- Company delay
- Panel dropout
- Student withdrawal
- Room unavailability

The generator itself must NOT perform scheduling or replanning.

## Simulation Assumptions

These assumptions are simulation choices for the technical assessment.
They are not claims about any specific real-world campus.

### Company Popularity

- Popularity is an internal score used to shape demand, day assignment,
  and shortlist pressure.
- Higher-popularity companies should generally receive larger shortlist
  targets, but eligibility and capacity constraints may still create
  some variation.

### Shortlist Generation

- Shortlists are generated from active, eligible students only.
- Student selection is weighted by CGPA margin above cutoff, branch fit,
  a marketability score, and an overlap-aware fairness term so that
  opportunities are concentrated toward stronger students without
  excluding most mid-band eligible candidates.

### Company Capacity

- Company shortlist targets are capacity-aware.
- Panel count, interview duration, and panel availability together define
  a company's notional interview handling capacity.
- Global shortlist demand should stay close to room capacity and below
  available panel capacity.

### Student Shortlist Distribution

- A minority of students may legitimately receive zero shortlists due to
  withdrawal, low CGPA, or limited overlap with company requirements.
- The distribution should be gradual: stronger students should usually
  receive more opportunities, but not through a single hard CGPA cliff.

### Placement-Day Distribution

- Day-1 should include several high-volume recruiters.
- Not all companies need multi-day presence.
- Per-day demand summaries should split company demand across available
  company-days using company-day panel capacity rather than counting the
  full company shortlist volume on every day.

### Availability Variation

- Availability remains deterministic under the seed.
- Students, rooms, and panels may have modest start/end-time variation
  or limited missing-day variation to avoid unrealistic identical shapes.
- The base dataset should still mostly represent normal operations.

### Capacity Sanity Thresholds

The base dataset should satisfy soft realism checks used by validation:

- Room demand/capacity ratio between 0.78 and 1.03
- Panel demand/capacity ratio at most 0.92
- Active zero-shortlist percentage at most 25%
- Active CGPA-to-shortlist correlation at least 0.45
- Company popularity-to-shortlist correlation at least 0.45
